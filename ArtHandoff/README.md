# ArtHandoff — lead ↔ art-specialist exchange

- **`requests/<batch>/`** — written by the lead (Claude Code):
  - `CODEX_ART_REQUEST.md`: the self-contained brief;
  - `INPUT_MANIFEST.json`: generated by `Tools/ArtPipeline/handoff.py request` from the live project;
  - `batch.json`: the asset list the manifest is built from;
  - `benchmark_layout.json`;
  - `references/`: current sprites and guides; only repo-owned files.
- **`returns/<batch>/`** — written by the specialist (Codex) only. Layout is in §8 of the request.
- The specialist never writes outside `returns/<batch>/`. The lead checks this at intake (`git status` scope check).

## Dispatch
**Automatic** (the interface was verified on this machine: Codex CLI 0.162 bundled in the VS Code extension `openai.chatgpt`, logged in with ChatGPT). The sandbox can write only to the returns folder:
```
codex exec -C ArtHandoff/returns/B01 -s workspace-write --skip-git-repo-check \
  -o ArtHandoff/returns/B01/_work/codex_last_message.md --json \
  "Read C:\Users\Winka\Projects\Aetherward\ArtHandoff\requests\B01\CODEX_ART_REQUEST.md and execute it completely." \
  > ArtHandoff/returns/B01/_work/codex_events.jsonl
```

**Manual fallback:** open Codex (VS Code panel or the desktop app) on this repository and send:
> Read `ArtHandoff/requests/B01/CODEX_ART_REQUEST.md` and execute it completely. Write only inside `ArtHandoff/returns/B01/`.

## Intake (lead)
```
python Tools/ArtPipeline/handoff.py intake  --batch B01 --validate
python Tools/ArtPipeline/handoff.py preview --batch B01 --overlay ArtHandoff/returns/B01/exports/Art --out ArtProduction/reviews/B01/after --tag b01
```
Nothing reaches `Assets/` until the batch passes intake, review and Unity verification, **and the owner approves the direction**. Import then goes through `Tools/ArtPipeline/ap.py import`: backup, journal, GUIDs preserved, rollback.
